# 图集捕手 · Image Grabber Pro

一个 Chrome / Edge 浏览器扩展（Manifest V3）：把网页里的图片尽可能**全都找出来**，然后批量下载。

针对"难抓"的场景专门做了处理——**懒加载、CSS 背景图、响应式 srcset、blob 地址、Canvas 绘制、iframe、
地址被转义/混淆、只靠 Referer 防盗链的站点**，都能抓。列表里的缩略图是降采样后的小图，
几十张图也不会拖慢浏览器；GIF 会保留原始动画，直接在卡片里播放。

页面里同一张图被反复引用（签名参数不同、尺寸参数不同、换了 CDN 域名上传了多份）时，只会显示一条，
并告诉你它是凭地址还是凭 MD5 认出来的。判定只用硬证据，不会把长得像但内容不同的图合并掉。

---

## 快速开始

1. 到 [Releases](../../releases/latest) 下载最新的 `ImageGrabber-Pro-x.y.z.zip`
2. 解压到任意**固定目录**（别放临时目录，删掉扩展就失效）
3. 打开 `edge://extensions/` 或 `chrome://extensions/`，开启 **开发人员模式**
4. 点 **加载解压缩的扩展**，选中解压出的文件夹（含 `manifest.json` 的那一层）
5. 打开任意网页，点工具栏的蓝色图标 —— 图就出来了

> 想让它在本地 `file://` 页面也能用？在扩展详情里打开「允许访问文件网址」。

## 怎么用

| 操作 | 说明 |
| --- | --- |
| 点图标 / `Alt`+`Shift`+`I` | 打开面板；图标上的数字是本页识别到的图片数 |
| 点缩略图 | 选中 / 取消；底部可「下载选中」「全部下载」 |
| 悬停卡片 | 下载 · 复制地址 · 在页面上定位 · 查看原图 |
| 打包 ZIP | 把选中的图片打成一个压缩包 |
| 大小滑块 | 调缩略图尺寸（72–260px），**只改显示，不重新加载** |
| GIF 动图 | 小/中等 GIF 直接在缩略图里播放动画，并带 `GIF` 标签；超过 6 MB 的显示静态首帧以避免卡顿 |
| GIF 筛选 | 类型筛选可选「GIF 动图」；尺寸筛选同样作用于 GIF，尺寸未知的 GIF 按小图处理，默认挡掉 1×1 埋点 |
| ☀️/🌙 · 快捷键 `T` | 切换主题。**默认浅色（纯白底）**——深色图片在深色底上几乎与背景融在一起，白底更易辨认 |
| 隐藏失效 | 筛掉缩略图加载失败的条目（通常是原地址已失效） |
| 合并重复 | 同一张图只显示一条：签名参数、尺寸参数不同的同一个文件，以及字节完全一致的重复上传，都能认出来。卡片带 `×N` 角标，悬停说明合并依据；关掉即看全部地址 |
| 每组最大 | 一键全选，但每组重复里只留分辨率最大的那张 |
| 深度 / 彻底 | 更激进的扫描：挖懒加载属性 / 逐元素读 CSS 背景 |
| 右键菜单 | 在图片上右键直接下载；空白处右键提取本页图片 / 直接下载全部；也支持下载链接指向的图片 |

快捷键：`R` 重扫，`Ctrl`+`A` 全选，`Ctrl`+`Enter` 下载选中，`Ctrl`+`Shift`+`D` 自检。

默认保存到 `下载/图集捕手/<站点域名>/<日期>/`，目录与文件名可在设置里用模板改，例如
`{host}_{index}_{w}x{h}` → `example.com_03_1920x1080.jpg`。

**文件名与面板一致**：面板上显示的名字就是落盘的名字。有些站点的图片地址只是存储服务的对象名
（一串 UUID，如 `0b3febed-43e5-4251-87f9-a42dd9ff9984`），真正有意义的名字写在 `alt` / `title`
里——这种情况会用页面上的名字命名，不会给你一串 UUID。想坚持用地址里的原始文件名，把模板改成 `{file}`。

## 它凭什么能抓到"难抓"的图

| 页面上的花样 | 怎么破 |
| --- | --- |
| 禁止右键、禁止选中 | 扫描在扩展层执行，不依赖页面事件 |
| 懒加载 / 滚动才出现 | 直接读元素属性（任意自定义属性名），不要求图片真的加载过 |
| 地址混淆、`\/` 与 `\u002F` 转义、无扩展名 | 自动反转义；路径像图片的标为「疑似」，可一键显示 |
| `background-image` 放图 | 解析 CSSOM（含 `@media`、CSS 嵌套、`image-set()`）+ 内联样式 |
| `blob:` 地址 | 回到页面上下文把 blob 读成文件再保存 |
| Canvas 绘制 | 直接读画布像素；跨域污染时改用**可见区域截图**兜底 |
| 视频当前帧 | 导出 PNG；受保护时同样走截图 |
| iframe 里的图 | 所有子框架一起扫描合并 |
| Shadow DOM 里的图与背景 | 递归遍历 `shadowRoot`，含自定义元素的 `background-image` 与 `<picture>` |
| 只给了 `srcset` 一档 | 把每一档分辨率都列出来，想要原图时不会只看到缩略图 |
| 缩略图地址 / `?w=300` 参数 | 推导原图候选（`_thumb`、`-300x200`、`/thumb/`、尺寸查询参数），标为「疑似」 |
| 懒加载图还没加载 | 深度模式会把 `data-src` 写回 `src` 唤醒它，缩略图就能直接读像素 |
| 防盗链（校验 Referer） | 双策略：先伪装成来源页 Referer，失败再**清空 Referer** 重试（部分站点把「无 Referer」当作直接访问放行），全程带登录 Cookie |
| 需登录才可见的图 | 抓取在扩展身份下进行，自动携带该站 Cookie |
| 地址藏在脚本里 | 扫内联脚本与 JSON-LD，转义地址也能认 |
| HEIC/AVIF 等新格式 | `createImageBitmap` 解不了时退回 `<img>` 解码，仍失败就原样输出 |

下载三级兜底：**扩展抓取（可伪装 Referer）→ 浏览器下载器 → 可见区域截图**。

### 为什么预览几乎不额外耗流量

Chromium 的 HTTP 缓存**按顶层站点分区**：扩展的 offscreen 文档属于 `chrome-extension://` 分区，
和网页所在分区互相隔离。所以早期实现里，打开面板会把页面上已经加载过的图片**完整重下一遍**
（实测 12 张图重复下载 15.96 MB）。

现在缩略图改由**页面内的内容脚本**生成：直接读取页面上已加载元素的像素（零网络），
必要时在页面分区里 `fetch`（命中同一份缓存）。实测面板阶段额外流量为 **0 字节**，
12 张大图从打开面板到出齐缩略图约 **0.2 秒**。

### 代码结构

```

src/content.js          页面扫描器：所有"找图"逻辑
src/background.js       Service Worker：采集调度、下载队列、防盗链、命名
src/offscreen.js/.html  跨域抓取、blob URL、缩略图降采样、ZIP、截图裁剪
src/hash.js             MD5：判断两份文件字节是否完全一致

src/naming.js           命名：面板显示名 == 落盘文件名
src/popup.*             弹窗面板
src/viewer.*            整页图库（右键菜单入口）
src/options.*           设置页
tools/                  测试与脚本（删掉不影响扩展运行）
```

## 常见问题

**图标上数字是 0，但页面明明有图？**
先滚动页面（懒加载的图要进过视口才存在），再按 `R` 重扫；仍不行就开「深度」+「彻底」。

**面板完全空白、连提示都没有？**
按 `Ctrl`+`Shift`+`D` 自检，它会指出卡在版本 / 标签页 / 内容脚本 / 页面无图 的哪一环。

**更新扩展后某些标签页还是抓不到图？**
在那几个标签页按一次 `F5`——已打开的页面里仍在运行旧版内容脚本。

**滚动时缩略图会不会反复刷新？**
不会。这里修过两轮：先是请求返回后无条件写回 `img.src`，即使元素已离开 DOM 或已被"预览不可用"
占位替换；再是开启「隐藏失效」时，每失败一张就整格重建列表，滚动到失效图区域会连着重建好几次。
现在缩略图有内存缓存，筛选、排序、主题切换都复用原卡片节点；失效项会合并成一次批量移除，
只删坏卡片、不新增节点。真机回归里滚动过程新增卡片数为 0、重复加载数为 0。

**面板里的输入框 / 下拉框文字发白看不清？**
表单控件的文字颜色、`-webkit-text-fill-color` 和 `color-scheme` 都已显式锁定，不跟随系统深色主题；
浅色底上的正文和占位文字都通过了 WCAG AA 对比度校验。

**缩略图显示"预览不可用"？**
通常是被抓页面自己引用了失效的图片地址（服务器 404）。下载通道会再试一次；确认没用可勾「隐藏失效」筛掉。

**有些大图一开始是空白 / 转圈？**
这是原图还在页面上下载。未加载完的图现在不会再占住缩略图并发队列，也不会触发扩展侧重复下载；
其它已就绪的图会先出现，等待中的卡片显示旋转指示，原图下载完成后自动补齐。

**GIF 会播放动画吗？**
会。6 MB 以内的 GIF 会直接使用页面缓存里的原始动画字节，卡片和图库都能看到完整动画，
并带 `GIF` 标签。超过 6 MB 的 GIF 仍显示静态首帧，避免单个大动图拖慢整个面板；下载得到的仍是原始 GIF。

**同一张图在页面里出现好多次，列表里怎么只有一条？**
默认开了「合并重复」，只有两种硬证据会让两条合并：

1. **地址归一**：同一个文件换了个写法——签名参数（`auth_key`、`X-Amz-*`）、尺寸参数（`?w=300`）、
   协议/`www` 前缀不同、参数顺序不同。归一后地址相同，就是同一个文件；
2. **MD5**：两份文件的字节完全一致——换了文件名、换了目录、换了 CDN 域名也能认出来。

卡片上的 `×N` 就是被合并的地址数，悬停会写明依据（"地址只是参数不同"或"字节完全相同"）。
关掉开关能看到全部地址；「下载选中」在任何情况下都不会把同一张图存两遍，
同一批下载里字节相同的也只落一份。

**为什么不做"画面相似"或"分辨率相同"的合并？**
两种都在真实站点上试过，都会误伤，已经移除：

- **画面相似**：卡牌 / 商品类页面所有图共用同一套外框，只有中间插画不同。粗粒度画面指纹分不开它们，
  实测把同一个页面上几十张不同的卡牌并成了一组。
- **分辨率相同**：一页几十张 300×300 的商品图分辨率当然一样，只看分辨率会把它们并成一张。
- **缩略后缀也不行**：`icon512-150x150.png` 和 `icon512-300x300.png` 名字只差尺寸后缀，
  但它们是两个不同分辨率的文件；页面里还常常同时存在 `icon512.png`，把三者归一等于替用户丢图。

所以现在的原则是：**宁可多显示一条，也绝不把不同的图合并掉。**
`test-dedupe.js` 里专门用 [pokemon.cn 的真实地址](https://www.pokemon.cn/tcg/product/22850.html) 做了回归用例。

**MD5 为什么不是所有图都有？**
只有真正抓到了原始文件字节才可能算（跨域图走页面缓存 fetch、以及下载阶段）。
同源图走的是"直接读已解码像素"的零流量通道，手上没有原始字节，所以它们只按地址归一合并。
用缩略图字节凑一个哈希是不行的：尺寸一变就对不上，而内容相近的两张图缩到同一尺寸反而可能撞上。
`test-duplicates.js` 里断言了每个地址的请求次数不因查重增加。

**下载下来的文件名和面板上显示的不一样？**
现在是一致的：面板上写什么名字，文件就叫什么名字。地址里只是一串 UUID / 哈希时，会改用页面
`alt` / `title` 里的名字。想强制用地址里的原始文件名，把文件名模板改成 `{file}`。

**列表里怎么混进来一个小图标（favicon）？**
站点图标也是图片，扫描器会一并列出。把尺寸筛选调到「≥ 300px」，或勾「隐藏失效」，就能把它挡在外面。
